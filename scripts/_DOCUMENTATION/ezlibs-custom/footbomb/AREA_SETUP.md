## 1. Map roles

| Role | Recognition | Example |
|---|---|---|
| Source / lobby | A Tiled object of type `FootBomb Controller`, or legacy `FootBomb Ref`, is registered by `object_registry` at startup | `footbomb` |
| Match instance | `EzMapInstance.get(area_id).metadata.game == "footbomb"` | An instance ID generated by FootBomb |
| Unrelated area | Neither condition is satisfied | `default` |

**Source identity is NOT inferred from an area name** or a prefix. The `Instance Map` property specifies the area **to clone** for a match; it does not determine whether the *current* area is a FootBomb source.

The observer stores Tiled referee discoveries at startup because handled objects can be cached/removed from Net's live area. Re-scanning `Net.list_objects` on `player_transfer` would therefore be unreliable.

`Config.DEFAULTS.INSTANCE_MAP = "footbomb"` is only a fallback match-template name, **not** a hardcoded source-area ID. The actual source/return area is stored on the match record when a referee interaction starts.

## 2. What moved from each map

The resulting **`areas/footbomb.tmx`** is 45×45. `footbomb.tmx` is the authoritative source for all FootBomb gameplay objects and their properties; its **199 authored soccer-field tiles** were preserved exactly (as tile IDs relative to their original tileset). The world placement is translated to align with the train-station map's existing field: **+3/+2 grid cells** for tiles; **+96/+64 map pixels** for authored objects. That translation applies during map authoring only, not at runtime.

Additional infrastructure copied from `footbombZ.tmx`:

| New element | Count / Tiled details |
|---|---|
| Cyber rail on Tile Layer 0 | 45 tiles |
| Elevated decoration on Tile Layer 4 | 12 tiles, including two platform tiles |
| Extra Tile Layer 3 and Object Layers 3/4 | Retained for station height/draw order |
| Passenger Train | Object **184**, name `train` |
| Platform Conductor | Object **182**, name `Rad Prog` |
| Connecting Custom Warps | Objects **183, 185, 186** |

All original FootBomb object IDs **148–159 and 166–168** are retained, including the goal, controller (**150**), original return warp (**149**), spawn positions, camera focus and bomb/defender points. Original properties remain intact. `footbombZ`'s alternative referee and its duplicates of game placements were not imported.

Tileset GIDs have been remapped onto unique, non-overlapping ranges. Do **not** copy integer GIDs from `footbombZ` manually: it contains duplicate `firstgid` values, which would conflict with `footbomb`'s valid tileset layout.

## 3. FootBomb Controller Tiled configuration

Create a regular point object in the map's object layer.

| Field | Required? | Value / behavior |
|---|---|---|
| Object **Type** | **Yes** | `FootBomb Controller` (recommended); `FootBomb Ref` is accepted for legacy maps |
| Object **ID, X, Y** | **Yes** | Automatically supplied by Tiled; X/Y locate the referee NPC |
| Object Name | Optional | `FootBomb Controller` (used as visible bot name) |
| `Instance Map` | Optional | `footbomb` by default; must name an existing map to clone |
| `Points to Win` | Optional | Positive integer used as the **initial host menu selection**; if invalid or absent, `Config.DEFAULTS.POINTS_TO_WIN` is used. The host may change it before starting the match. |
| `Asset Name` | Optional | `ref-prog` by default; selects the bot PNG |
| `Animation Name` | Optional | Defaults to `Asset Name` when empty; `.animation` file |
| `Mugshot` | Optional | `ref-prog-mug` by default; selects portrait PNG |
| `Mug Animation Name` | Optional | Default mug animation from constants if not set |
| `Direction` | Optional | Defaults to `Down` for the NPC; current map uses `Down Right` |
| `Dont Face Player` | Optional | Boolean; currently passed to bot creation as `true` only for an actual Lua boolean `true` |

**Actual current map example** (`footbomb.tmx`, object ID **150**):

```text
Name              = FootBomb Controller
Type              = FootBomb Controller
X / Y             = 800 / 800    (in merged 45x45 map)
Instance Map      = footbomb
Asset Name        = ref-prog
Animation Name    = ""          (falls back to ref-prog)
Mugshot           = ref-prog-mug
Mug Animation Name = mug
Direction         = Down Right
Points to Win     = 5
```

Note: legacy `FootBomb Ref` properties such as `Intro Message`, `Question`, and `Started Message` are not read by the current FootBomb interaction implementation. **The current referee uses the Nebulous Liberations 9-slice menu**, with four choices: `[VS] NPC`, `[VS] Player`, `Explanation`, `Cancel`. No extra Tiled property is required to enable the menu.

### Referee gameplay menu

- `[VS] NPC`: the host configures the winning score and Grace, then launches a private NPC match.
- `[VS] Player`: the first player configures the winning score and Grace, then waits for an opponent. The second player chooses `[VS] Player` followed by `Join Match`. Only the first player (host) controls the rules.
- `Explanation`: the referee menu is completely removed before native dialog is shown. All explanation textboxes use the referee's `Mugshot` and `Mug Animation Name` paths. Once the **last** textbox closes, the main menu appears again. There is no extra persistent input lock.
- `Cancel`: dismisses the menu. Cancel in match setup returns to the four-choice menu.

**Match setup:** The `FootBomb Setup` menu has exactly four rows: `Winning Score: < N >`, `Grace: < On/Off >`, `Start Match`, and `Cancel`. Move through rows with Up/Down; while the Winning Score row is selected, Left decreases and Right increases by **1 per press or input repeat**, with a minimum of 1. On the Grace row, Left selects Off, Right selects On, and Confirm toggles. Confirm on Winning Score leaves the editor open; Confirm on Start Match applies the rules. Confirm on Cancel or the controller Cancel button exits setup and reopens the referee's four-choice menu. All input and capture management remains handled by PlayerInterface through the shared `OptionMenu.select`.

**No backdrop flicker:** All FootBomb referee menus enable `stable_text=true`. The shared menu constructs the header/body 9-slice panels once, reserves width for numeric changes, then updates only text glyph sprites as the selected row or value changes. It does not call `setChildren`, reposition a panel, or create another panel for navigation/adjustments. Closing one menu to open a *different* menu, or intentionally suppressing it for explanation textboxes, still removes the old panels normally.

**Grace (default on):** The existing match-point rule gives the trailing side a final chance after the target is reached. Turn it off to end the match immediately when a player reaches the target. The default is `Config.DEFAULTS.GRACE_ENABLED = true`; there is no new Tiled property for Grace. Actual match settings are stored in instance metadata, `points_to_win` and `grace_enabled`.

[Full menu API and lifecycle](referee_menu/index.md).

## 4. Required match points

`find_named_spawn_points` in `footbomb/main.lua` **requires these exact 12 names** as Tiled point objects in the cloned map. These are not optional:

| Role | Exact Tiled object Name |
|---|---|
| Player starts | `Player 1 Spawn`, `Player 2 Spawn` |
| Kicker movement | `Kicker`, `Move Forward` |
| Defense positions | `Defender 1`, `Defender 2`, `Defender 3` |
| Bomb positions | `Bomb`, `Bomb 1`, `Bomb 2`, `Bomb 3` |
| Camera location | `Camera Focus` |

Tiled supplies each object's X/Y position; the `z` value uses the engine area object position (with a Lua fallback of 0). Missing names stop match creation and produce a detailed missing-point error. The combined `footbomb.tmx` retains all twelve from the original FootBomb map, translated consistently onto the larger map.

## 5. Train station and warps

### Passenger train (`footbomb.tmx`, object 184)

```text
Name        = train
Type        = Passenger Train
Start       = 1,38
Stop        = 27,38
End         = 38,38
Direction   = Down Right
Platform Z  = 3
Train Z     = 0
Speed       = 4
Color       = Green
```

The train system requires `Start`, `Stop`, `End`, `Direction`, `Platform Z`, `Train Z`. `Speed` and `Color` are optional. The `Name` must match the conductor's `Train` property and the train at the source station (`default` uses `train`).

### Station conductor (`footbomb.tmx`, object 182)

```text
Name   = Rad Prog
Type   = Conductor
Train  = train
1 Area = default
1 Type = Area
1 Name = Highway
```

`Train` and `1 Area` are required by the Indy Trains parser. The numbered destination Type/Name fields are optional. `default.tmx` conductor **78** selects FootBomb through `3 Area = footbomb`, `3 Type = Area`, `3 Name = FootbombArena`.

### Linked warps

| Source | Destination | Purpose |
|---|---|---|
| `footbomb` warp **183** | `footbomb` warp **185** | Station → field |
| `footbomb` warp **185** | `footbomb` warp **183** | Field → station |
| `footbomb` warp **186** | `FootBombers` warp **26** | Original extra exit to FootBombers |
| `footbomb` warp **149** | `default` object **145** | Original FootBomb return warp preserved |

For a `Custom Warp` object, set `Type = Custom Warp`; `Target Area` and `Target Object` are needed for area transfers; `Direction`, `Warp In`, and `Warp Out` control orientation/animation. `Dont Teleport = true` is an optional special behavior. Linked target object IDs must exist in the target map.

## 6. Observer logging and diagnostics

`area_observer.lua` logs from actual object/instance membership:

```text
[footbomb] AREA_DISCOVERY: source registered area=footbomb referee_id=150 referee_type=FootBomb Controller identity=canonical instance_template=footbomb
[footbomb] AREA_OBSERVER: event=player_transfer player=<id> area=footbomb role=source previous_area=default previous_role=other source_referees=150:FootBomb Controller source_templates=footbomb instance_id=none template_area=none tracked_instance=none
[footbomb] INSTANCE_FLOW: cloning FootBomb template=footbomb source_area=footbomb referee_id=150 mode=npc
```

Log lines may include `identity=legacy` for `FootBomb Ref` maps; this is intentional compatibility. At startup the observer also emits `AREA_DISCOVERY: WARNING ... Instance Map=...` if a referee points to a template absent from `Net.list_areas()`. Player moves in unrelated areas are not spammed, but leaving a FootBomb area is logged.

Read-only APIs available on the FootBomb module:

```lua
local FootBomb = require('scripts/ezlibs-custom/footbomb/main')
local role = FootBomb.get_area_role('footbomb') -- 'source' | 'instance' | nil
local info = FootBomb.get_area_diagnostic('footbomb')
-- info.role, info.source_referees, info.source_templates,
-- info.instance_id, info.template_area, info.source_referee_count
```

The observer does not hook new network events; the existing FootBomb plugin's `handle_player_join` / `handle_player_transfer` / `handle_player_disconnect` receive events as before.

## 7. Deployment and verification

1. Backup `areas/footbomb.tmx` and `areas/default.tmx` and stop the server.
2. Copy both full map files and the three Lua files under `scripts/ezlibs-custom/footbomb/` from the patch.
3. Restart to reload both map data and startup object caches. Confirm **`AREA_DISCOVERY: source registered area=footbomb ...`** and the train parser's **`Found the 'train' passenger train in footbomb.tmx`**.
4. Use the **FootbombArena** train destination from the `default` conductor. The destination should now be `footbomb`, with no `destination_train` nil error and no source-area mismatch.
5. Walk between train station, playing field, and optional exits. Interact with the `FootBomb Controller` and start a match; verify the instance spawns, camera, role selection, and return-to-source behavior.
6. Test with two players to confirm match-instance observation and cleanup. Live tests are still required; this patch is statically/offline validated, not ONB-client certified.

The old `footbombZ.tmx` is **not overwritten or deleted**. It remains a legacy area if still loaded by the server; after confirming no external links/scripts depend on it, you may archive it separately. It is not used by the updated `default` conductor route or the new station's internal warp links.
